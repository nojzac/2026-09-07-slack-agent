What "bot foundations" means in plain words
  • Before any AI, you need the plumbing.
  • A Slack app that is allowed to hear mentions and post replies.
  • A web address that Slack calls when someone tags the bot. It lives on Vercel.
  • Two secrets so Slack and your code trust each other.
  • This lesson builds that plumbing and proves it with the dumbest possible reply, a random number.
Why a random number

  • If the number shows up, Slack, Vercel and the secrets are all right.
  • Any trouble later is then the AI part, not the plumbing.

Why it works this way the reasons behind each part of the goal
Why the bot has to live on the internet at all
  • Slack does not run your code. When someone tags the bot, Slack sends a web request to an address you give it, and waits for your reply.
  • Your laptop has no public address and is often asleep, so the code needs a home on the internet that is always reachable.
Why Vercel
  • Vercel is a hosting service that gives your code a public HTTPS address for free, which is exactly what Slack needs.
  • It deploys straight from GitHub: push code, it goes live. No servers to set up, no uploads.
  • Claude Code knows Vercel well, so it can create the project and deploy without you learning the tool.
  • It is Ray's choice, not a rule. Any host with a public address would work, but every later lesson assumes Vercel.
  • It persists. This one Vercel project and one repo carry the whole course. Every later lesson pushes to the same repo and Vercel redeploys the same project. You never create a second one.
What a serverless function is, and why this is one
  • A serverless function is one piece of code that runs only when a request arrives, then stops. There is still a server, but Vercel owns it and starts your code on demand.
  • Here it is a single file, api/slack/events.js. Slack calls it, it checks the secret, posts the random number, and exits.
  • Why it fits: the bot sits idle most of the day. A function costs nothing while idle and needs no maintenance, unlike a server you keep running.
  • Later Slack expects an acknowledgement within three seconds, and Vercel functions have a time limit. Lesson 05 handles both: the function answers Slack at once, keeps working in the background, and Ray raises its limit to about 13 minutes in vercel.json.
  • Later The cloud sandbox in lesson 05 is not a workaround for the time limit. It exists because Claude Code needs a real machine with files and tools, which a function does not have.
Why a private GitHub repo, and what it does
  • It is what Vercel deploys from. Vercel watches the repo. Every push becomes a new live version. Without the repo there is no automatic deploy.
  • It is your history and backup. Each lesson adds a commit, so you can look back or roll back. Ray's own repo is tagged one checkpoint per lesson for exactly this reason.
  • Private because it is your bot's guts. The code, the manifest with the bot's name, and later the memory, skills and rules you write are yours. Secrets themselves never go in the repo, only in Vercel.
  • Later Not to be confused with lesson 08, "Connecting to GitHub". That lesson gives the agent access to GitHub so it can work on your other repos. This repo is where the agent's own code lives.
How one message flows what happens in the two seconds after you tag the bot
1
You, in Slack post @Joestar hello in a channel.
2
Slack sees the mention, wraps it in a JSON message, signs it with your signing secret, and POSTs it to your endpoint on Vercel.
3
Vercel wakes up api/slack/events.js for this one request and hands it the environment variables.
4
Your function recomputes the signature. Mismatch means reply 401 and stop. Match means read the event.
5
Your function picks a random number and calls Slack's chat.postMessage API with the bot token, asking for the reply to go in the thread.
6
Slack posts the reply as Joestar. Your function answers Slack's original request with 200 and exits.
Two things to notice
  • Two separate conversations with Slack are happening: Slack calling you (secured by the signing secret) and you calling Slack (secured by the bot token). That is why there are two secrets.
  • Later Slack gives you about three seconds to answer step 2. If you are slow it resends. Fine for a random number, a problem once an AI is thinking. Lesson 05 changes the order: answer Slack first, then keep working.

3Start creating the Slack app from a manifest
  • Open api.slack.com/apps → Create New App → From a manifest.
  • Choose your test workspace → Next. Leave this tab open, it now wants a manifest.
  • A manifest is a small text file that tells Slack the bot's name, what it may read, and what it may post.

Phase C · Deploy and hand over the secrets steps 5 to 8 · GitHub, Vercel, two secrets
5Let Claude set up git, a private GitHub repo, and the Vercel project
  • When Claude finishes the code it asks whether to run git init and set up Vercel. Ray answers:
Yeah, set up git init and then push it to a private GitHub repo and then set up the Vercel project for me.
  • When it is done it lists the two environment variables Vercel needs: SLACK_SIGNING_SECRET and SLACK_BOT_TOKEN.
6Copy the signing secret from Slack into Vercel
  • Slack app page → Basic Information → App Credentials → Signing Secret → Show → copy.
  • Vercel → your project (joestar-agent) → Settings → Environment Variables → Add.
  • Key SLACK_SIGNING_SECRET, paste the value, environment Production only → Save.
  • This secret is how your code checks that a request really came from Slack.
7Install the app to the workspace and copy the bot token into Vercel
  • Slack app page → Install App → Install to [workspace] → allow.
  • Copy the Bot User OAuth Token. It starts with xoxb-.
  • Vercel → add a second variable: key SLACK_BOT_TOKEN, paste, Production only → Save.
  • This token is how your code is allowed to post messages as the bot.
8Tell Claude the secrets are set and get the endpoint URL
Hey, so I also set the environment variables too.
  • It redeploys and gives you the events endpoint. It looks like https://joestar-agent.vercel.app/api/slack/events.
  • If it does not print the URL, ask for it.
Phase D · Connect Slack to the deployment and test steps 9 to 10 · the moment it comes alive
9Point Slack's Event Subscriptions at that URL and wait for "Verified"
  • Slack app page → left menu → Event Subscriptions (in Ray's video it sat just under "MCP Servers"; Slack moves menus, so search the sidebar if it is elsewhere) → paste the URL into Request URL.
  • Wait for the green Verified tick → Save Changes.

What Claude wrote for you the five files, and what the one that matters does
The five files
api/slack/events.js the whole bot, about 100 lines slack-manifest.json what you pasted into Slack in step 4 .env.example names of the secrets, values left blank package.json tells Vercel this is a Node project .gitignore keeps .env and node_modules out of git
  • The path api/slack/events.js is not arbitrary. On Vercel, any file under api/ becomes a serverless function at the matching URL. That is how the endpoint gets its address.
events.js, top to bottom
  • Read the secrets from environment variables. If either is missing, answer 500 and log it. This is the error you get if step 6 or 7 was skipped.
  • Read the raw body exactly as Slack sent it. The signature covers the exact bytes, so the code must not parse and re-serialize first. Claude added a comment saying so.
  • Verify the signature. Rebuild it from the timestamp plus body using the signing secret, compare in constant time, and reject anything older than five minutes so a captured request cannot be replayed.
  • Answer the URL verification challenge. When you paste the endpoint in step 9, Slack sends a one-off message containing a challenge string and expects it echoed back. That echo is what turns the tick green.
  • Ignore retries. If Slack's retry header is present, answer 200 and do nothing. Otherwise a slow first attempt would produce two numbers.
  • Handle the mention. If the event is an app mention and not from a bot, pick a random number and post it. Reply goes to the existing thread if there is one, otherwise it starts a thread on the message.
  • Answer 200. Slack is satisfied and stops.
Why this matters for later lessons
  • Every later version of the bot keeps this skeleton: verify, dedupe, handle, acknowledge. New lessons add what happens inside "handle".
  • When something breaks later, the first three checks are always the same: are the secrets set, is the signature passing, is Slack retrying. Knowing the file makes those checks fast.
Where you would change it the seams, if you wanted to make it your own
Reply with something other than a number
  • One place: the "handle the mention" branch in events.js. Everything before it (verify, dedupe) and after it (answer 200) stays.
  • This is exactly the seam lesson 05 uses to swap in Claude Code.
Change the number range
  • No code change. Set RANDOM_MIN and RANDOM_MAX in Vercel's environment variables and redeploy.
Respond to direct messages, not only @mentions
  • Three places, all in step: the manifest needs the im:history scope and the message.im event, then re-upload it on the Slack app page.
  • Re-install the app, because scopes changed. That gives a new bot token to paste into Vercel.
  • In events.js, the check for app_mention has to also accept the direct-message event type.
  • General rule: any new thing you want the bot to see or do is a manifest change plus a re-install plus a code change, in that order.
Rename the bot
  • Display name lives in the manifest. Edit and re-upload on the Slack app page. No code or redeploy needed.
What "done" looks like three checks
  • You tag the bot and it replies in the thread with something like 🎲 42.
  • Tagging it again inside that thread replies in the same thread.
  • Project on disk has five files: api/slack/events.js, slack-manifest.json, .env.example, package.json, .gitignore.
When it goes wrong by symptom, then what happened to Ray
No green "Verified" tick in step 9
  • The deploy is not live yet. Open the Vercel project and check the latest deployment finished.
  • Or the signing secret is missing or wrong in Vercel. The function answers 500 if it is missing and 401 if it is wrong. Vercel's function logs show which.
  • Retry the URL after fixing. Slack re-sends the challenge each time you paste.
Green tick, but no reply in Slack
  • The bot is not in the channel. Run /invite @Joestar first.
  • The bot token is missing or from before a re-install. Copy it again from Install App and re-save in Vercel.
  • Check Vercel's function logs for "chat.postMessage failed", which names Slack's reason.
Two replies to one mention
  • Slack retried because the first attempt was slow, and the retry was not ignored. Ray's code checks the retry header, so this only happens if that check was lost.
An error about a missing value
  • One of the two environment variables is not set for the environment that deployed. Both must be on Production.
What happened to Ray
  • He saved the bot token to all environments by mistake, then re-saved it as Production only. Not fatal, just tidier.
  • The manifest's request URL was a guess because Vercel had not deployed yet. Slack let him create the app anyway and he set the real URL later in Event Subscriptions. Expect the same.
Settings and secrets two required, two optional
Vercel environment variables, Production only
  • SLACK_SIGNING_SECRET from Slack → Basic Information → App Credentials.
  • SLACK_BOT_TOKEN from Slack → Install App, starts with xoxb-.
  • Optional: RANDOM_MIN and RANDOM_MAX. Defaults 1 and 100.
Slack app settings
  • Manifest from step 4.
  • Event Subscriptions request URL from step 9.
  • Bot event app_mention.
Never commit the secrets
  • The repo ships a .env.example with empty values.
  • The .gitignore excludes .env, so a local copy with real values stays off GitHub.

Look up a word eight terms this lesson introduces, for when one trips you
Slack app
  • Slack's word for anything that plugs into a workspace. Your bot is one app.
  • It is registered on api.slack.com, separately from the workspace.
Manifest
  • A short text file describing the app: its name, what it may read (scopes), what events it wants, and where to send them.
  • Step 4. You can edit it later and re-upload.
Scope
  • A single permission. app_mentions:read means "may see messages that mention me". chat:write means "may post".
  • Each new feature in later lessons adds scopes.
Bot token
  • A long string starting xoxb- that proves to Slack "this request is from that bot". Your code sends it with every reply.
  • Step 7. Treat it like a password.
Signing secret
  • A different string Slack uses to sign every request it sends you. Your code recomputes the signature and rejects anything that does not match.
  • Step 6. Stops strangers from faking Slack.
Environment variable
  • A named value the hosting platform hands to your code at run time, so secrets never sit in the code or the repo.
  • Vercel calls the page Environment Variables. Steps 6 and 7.
Endpoint
  • The public address that receives Slack's requests. Here it is /api/slack/events on your Vercel domain.
  • Step 8.
Event Subscriptions
  • The Slack setting where you say "send me these events, to this endpoint".
  • Slack tests the endpoint first with a challenge, hence the Verified tick. Step 9.
