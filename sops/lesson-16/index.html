SLACK AGENTS · CHAPTER "0 TO 1" · LESSON 16

A second opinion from a different model: Codex in the sandbox

The bot reviews its own work with its own subagents, which means it checks itself using the same instincts that wrote the code. This lesson puts OpenAI's Codex CLI in the sandbox so Claude can hand a commit to a model that is not Claude and report back what it said. The install is easy. The interesting parts are that the credential is a ChatGPT login rather than an API key, and that the only safe place to put it is a file.

Ray's video: 2 min 39 sThis page: 90–150 minAt the end: "get a second opinion on this" returns a PASS/FAIL verdict in the thread

What you'll have at the end

The split is the whole design: the binary is baked into the image once, the credential is written per run and never enters the environment of anything else.

  • The Codex CLI in the sandbox image, pinned, so every run has it with nothing to install.
  • A credential written per run as a file — never an environment variable of anything else.
  • A skill with three modes (review, challenge, consult) and the CLI failures already paid for.
  • A verdict in Slack in Codex's own words, with the agent's own read underneath it.

Who this is for, and what it assumes

You finished lesson 15, so the bot has skills, a persona, and opens pull requests against its own repository. You can rebuild the E2B template — bin/with-secrets node e2b/build.mjs — and you have a ChatGPT Plus or Pro subscription you are willing to lend to a bot.

This lesson spends a personal account rather than a service credential, so it has an explicit decision as step 1. It also contains the most instructive code review on any of these pages.

Why this lesson exists

Every lesson so far widened what the bot can do. This one is the first that adds a check on whether it did it well — and the first that spends a personal account to get one.

The point is not that Codex is better. It is that it is different. A second Claude pass shares Claude's blind spots; a second model does not. Ray uses this constantly — in his own bot a feature request went through two rounds of Claude review and a Codex review before he looked at it.

Before you begin

This lesson hands your ChatGPT account to everyone who can message the bot. There is no per-user scoping here. Any workspace member can trigger a run, and any run can shell out to Codex under your login. That is already true of the bot's GitHub token — the difference is that this one is a consumer subscription with your name on it. If that is not acceptable, use an API key or skip the lesson.

The second thing to decide before you type: the credential is a file, never an environment variable of the Claude run. It is the one design choice in this lesson that is hard to retrofit, because by the time you are reviewing a diff you are arguing with something already built.

PART 1

Understand what you're building

Four things: what a second model buys that a second Claude pass does not, why the credential is shaped so strangely, the one place it is allowed to live, and what the whole arrangement costs.

What Codex is doing here: one model checking another's workA reviewer that does not share Claude's blind spots, running inside the same throwaway box.

UNDERSTAND

The bot already reviews its own work — lesson 09 gave it subagents, and a second Claude pass catches real bugs. What it cannot do is disagree with itself from outside its own training. Codex is OpenAI's command-line coding agent; put it in the sandbox and Claude can shell out to it mid-run, hand it a commit, and get back findings written by a model that made different mistakes.

It is a second pair of eyes, not a second opinion you have to ask for. Claude drives it. You say "get a second opinion on this" in the thread; the skill turns that into a codex review call, and what comes back is summarised into the thread rather than pasted.

Two halves, and they live in completely different places. The binary is baked into the E2B image, because a fresh sandbox per message turns every install into a per-message cost — the same argument as Playwright in lesson 11. The credential is written per run, because a secret in an image is a secret in every copy of that image forever.

Ray uses @openai/codex@latest; this workshop pins it. The version lives beside the others in api/_lib/versions.js as CODEX_VERSION = '0.154.0'. A template build has to be reproducible, not silently pick up whatever npm published overnight.

The credential is a ChatGPT login, not an API keyWhich is why one environment variable holds the entire contents of a file.

UNDERSTAND

Codex authenticates from ~/.codex/auth.json, written by codex login. That command opens a browser. There is no browser in a serverless function and no human at the keyboard of a sandbox, so the login cannot happen there — the only way in is to log in once on your own machine and carry the resulting file across.

Hence the shape that looks wrong the first time you see it: one environment variable, CODEX_AUTH_JSON, containing a whole JSON file on a single line. It is not a key-shaped secret because it is not a key. It is a session.

Ray says the token runs on roughly a ten-day clock and then needs re-pasting. Untested here. Nothing in this workshop has yet watched one expire, and it is not known whether a stale token fails loudly or just makes Codex go quiet mid-run. Treat "Codex stopped working" as "re-mint the credential" until someone has seen the failure mode.

You can bill Codex against an API key instead. Ray does not, and neither does this page: the ChatGPT subscription is already paid for, and an API key would mean metered spend on every review.

Where the credential may go, and where it must notA file in the box, at mode 600. Not an env var, not a command string, not a log line.

UNDERSTAND

Since lesson 08 this repository has had one rule about secrets and the sandbox: a capability belongs in the image, a secret does not. Codex adds a second rule, because its secret has to end up inside the box to be usable at all. Where exactly it lands is the whole of the security design.

Route inVerdict
sandbox.files.write to ~/.codex/auth.json, then chmod 600This is what we do. Only the codex process ever opens it. The chmod command string contains paths and nothing else
The envs object of the claude -p runNo. Every Bash command the model runs would inherit it, and it would sit in the process environment for the life of the run
Sandbox.create's runtime envsWorse. Same exposure, but for every process in the box including ones we did not start
Interpolated into any command stringNo. Process listings and shell history are both readable from inside the box
console.warn(err.message) after a failed parseNo — and this one shipped. V8's JSON.parse error message embeds the input it choked on, so a malformed credential would print its own first characters into Vercel logs
The last row is the point of the review step. It is not a route anybody chose; it is a route that appeared by accident in a line of defensive error handling, and it took a reviewer who asked "what exactly does that message contain?" to find it. Step 3 of this page is where that happens.

What 339 MB and a personal account cost youThe image grows, the blast radius grows, and neither is reversible by a revert.

UNDERSTAND

The linux-x64 platform package for Codex unpacks to 339 MB, and the sandbox image grows by that. That is a real cost paid on every template build and every cold sandbox boot, in exchange for a reviewer you will use on maybe one message in five.

Anyone who can message the bot can make Codex run under your ChatGPT account. There is no per-user or per-channel scoping in this bot: every tool it holds is held on behalf of everyone in the workspace. That is already true of the GitHub token and the Exa key; Codex is the first one that is tied to a personal consumer subscription rather than a service credential. Decide that you are fine with it before step 2, not after.
The upside is concrete and you can see it in step 8. A planted one-line bug in mrkdwn.js — bullet conversion silently dropping the item text — was found by Codex, reported as a [P1] at mrkdwn.js:64, in 45 seconds. That is the whole value proposition, tested once.

const CODEX_CONFIG_TOML = `model_reasoning_effort = "high"
approval_policy = "never"
sandbox_mode = "danger-full-access"
`;

export async function setUpCodex(sandbox) {
  const authJson = process.env.CODEX_AUTH_JSON;
  if (!authJson) return;                       // unset means "no codex here", not "broken"

  try { JSON.parse(authJson); } catch {
    // Never log err.message: V8's SyntaxError embeds a slice of the input.
    console.warn('[codex] CODEX_AUTH_JSON is not valid JSON');
    return;
  }

  try {
    await sandbox.files.write(`${SANDBOX_HOME}/.codex/auth.json`, authJson);
    await sandbox.files.write(`${SANDBOX_HOME}/.codex/config.toml`, CODEX_CONFIG_TOML);
    const res = await sandbox.commands.run(
      `chmod 700 ${SANDBOX_HOME}/.codex && chmod 600 ${SANDBOX_HOME}/.codex/auth.json`,
    );
    if (res.exitCode !== 0) console.warn('[codex] chmod exited', res.exitCode);
  } catch (err) {
    console.warn('[codex] could not configure the sandbox for codex:', err.message);
  }
}
