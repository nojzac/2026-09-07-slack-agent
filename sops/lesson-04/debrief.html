Why the secrets deviate from the video

Ray pastes both values into Vercel's dashboard and keeps a .env.example in the repo. This project's own rule (CLAUDE.md) is stricter: secrets live in 1Password only, and .env.op holds op:// pointers instead of an example file. Same end state in Vercel — the values just never pass through a browser form, a file, or this transcript.

Why it didn't work, and what fixed it

Two separate stalls, one after the other.

First: the placeholder URL

The Request URL box contained https://<deployment>/api/slack/events — the literal placeholder from the manifest, pasted before I'd filled in the real domain. No such host exists, so Slack reported "Your URL didn't respond."

Second: Verified, but never saved

You pasted the real URL, Slack said ✓ Verified — and nothing was saved. The lesson page calls this out, and it's the one thing the green tick doesn't tell you:

Verified proves Slack can reach your endpoint. Save Changes is what makes Slack actually send you events. They are different things, and the save bar sits off the bottom of a long page.

That's the entire explanation for the silent hour. Everything else was already correct.

How I proved where the fault was

Rather than guess, I tested each link in the chain separately — worth knowing, because you'll debug this shape of problem for the next fourteen lessons:

  • curl the endpoint → 200 slack events endpoint: ok. The deployment is alive.
  • A hand-signed url_verification → challenge echoed. The signing secret in Vercel matches 1Password's.
  • A deliberately mis-signed request → 401. The signature check is real, not decorative.
  • A direct chat.postMessage with the bot token → posted. Token, chat:write, and channel membership all fine.
  • A hand-signed app_mention POSTed to production → the threaded number appeared. The handler works end to end.
  • A real mention typed by you → nothing arrived. Everything I could test passed, so the fault had to be upstream, in Slack's dispatch.

That last line is what pointed at unsaved settings. I guessed "reinstall the app" first, which was wrong — the save was the missing piece.
